# ASVS 5.0 mapping: encoding, validation, business logic, file handling (Stage 2)

Standard: OWASP ASVS 5.0.0 (requirement text from the official `5.0.0` CSV). IDs are `v5.0.0-<chapter>.<section>.<requirement>`; text is shortened here, see the standard for the full wording.
Target: Level 2 overall, Level 3 for authentication and session management (docs/kit/08). This file covers the chapters whose surface Stage 2 introduced: V1, V2 and V5. V3 (web frontend) and V4 (API) are mapped with the stage that finishes that surface (F15). Authentication, sessions and authorization are in `asvs-matrix.md`.

**Summary.** 56 requirements: 33 met, 6 partial, 1 not met, 16 not applicable. By level: L1: Met 13/N/A 2/Partial 1, L2: Met 18/N/A 11/Not met 1/Partial 1, L3: Met 2/N/A 3/Partial 4.

Partial and not-met rows are in `docs/cutlist.md`. The common reason is the same and deliberate: untrusted archives are parsed only in the sandbox (Stage 3), so the full file checks exist, are tested, and are not yet attached to the upload. A human must read this table and the upload and rendering code before Stage 2 is signed off.
